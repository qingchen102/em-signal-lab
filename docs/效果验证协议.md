# 效果验证协议

这份文档说明「信号实验室」怎么证明自己有用 —— 不是「我们觉得有用」，而是
**可复现、可核对、能被反驳**的那一种。

对应黑客松自由命题要求的第三段（方案：如何解决，并验证效果）。

---

## 1. 为什么需要一份协议

教学类作品最容易滑向的失败模式是：**演示很好看，但没有任何证据说明学生真的学会了。**

常见的三种自我安慰：

| 说法 | 为什么不算证据 |
| --- | --- |
| 「学生都说好玩」 | 好玩和学会是两件事。喜欢玩示波器的人未必分得清时域和频域 |
| 「访问量 / 使用时长很高」 | 只能说明没崩，不能说明学到了 |
| 「我们讲了原理，逻辑是对的」 | 逻辑对不等于人学会了。教学的效果只能从人身上量 |

所以需要一个**能在 30 分钟内跑完、结果能被第三方复核**的测量流程。

## 2. 设计：平行卷 + 锚题

### 2.1 两份卷子，同一份蓝图

前测和后测各 10 道单选题，覆盖五个知识点：

| 知识点 | 题号 | 考什么 |
| --- | --- | --- |
| 时域基本量 | t1 t2 | 从示波器屏上读周期求频率、读峰峰值求振幅 |
| 采样定理 | s1 s2 | 折叠频率计算、每周期采样点数 |
| 频谱与谐波 | p1 p2 | 读基波频率、方波为什么只有奇次谐波 |
| 示波器操作 | i1 i2 | 触发丢失的原因、AC 耦合吃掉了什么 |
| 阵列测向 | a1 a2 | 读来波方向、解释栅瓣 |

两份卷子由 `app/js/quiz.js` 的同一份生成器蓝图产出，只是种子不同。

### 2.2 六道平行题 + 四道锚题

- **6 道平行题**（t1 t2 s1 s2 p1 a1）：题干里的数字换了，考同一个能力。
- **4 道锚题**（p2 i1 i2 a2）：**两套卷子一字不差**，连选项顺序都一样。

锚题是这份协议里最关键的一环。

**为什么必须有锚题：** 如果只比较「前测平均分」和「后测平均分」，有一个致命的
混淆变量 —— 你没法排除「后测那套卷子恰好更容易」。教育测量里这叫**不等值**。
锚题的作用是把两套卷子钉在一起：如果同一批人在锚题上的表现没有系统性差异，
就有理由认为两套卷子的难度大致相当，那么总分的变化更可能来自学习而不是卷子。

这不是严格的等值设计（真正的等值需要更大的锚题比例和统计模型），
但对一个 3 天的作品来说，**「有没有锚题」是分水岭**：有锚题的比较可以被讨论，
没有锚题的比较连讨论的资格都没有。

### 2.3 题目里的图是真画出来的

每道带图的题，图都是用**实验台自己的绘图函数**渲染的
（`NS.scope.draw` / `NS.spectrum.draw` / `NS.array.draw`，`clean: true` 模式）。

这一点很重要：学生在仪器上看到什么，考卷上就是什么。不会出现
「课上教的示波器长这样，考卷上的图是另一个人用 matplotlib 画的」这种断裂。

`clean: true` 会关掉所有直接写出答案的标注（比如「1.00 kHz 基波」这种标签），
保证图上读不出答案。

## 3. 怎么跑

### 3.1 三种规模

| 规模 | 人数 | 需要的时间 | 能得出什么 |
| --- | --- | --- | --- |
| 自查 | 1 人 | 15 分钟 | 只能验证流程跑得通，**不能**当效果证据 |
| 小样本 | 5–10 人 | 40 分钟 | 能看出明显的卡点，不能做统计推断 |
| 一个班 | 20 人以上 | 一次课 | 能报告配对均值差和置信区间 |

**最少需要 5 人**才能跑出有意义的配对数据。

### 3.2 操作步骤

1. 打开 `app/index.html`，点顶栏的**效果验证**。
2. 在「代号」里填一个**同一个人前后测都用同一个**的代号（学号后四位、昵称都行）。
   代号只存在本机浏览器里，不会上传。
3. 选「前测」→ 开始答题 → 交卷。记下分数。
4. **让学生自由使用实验台 20–30 分钟**（自己调旋钮、问 AI 助教、看知识卡片）。
5. 回到效果验证 → 选「后测」→ 填**同一个代号** → 开始答题 → 交卷。
6. 点「看汇总」，读**配对明细**那张表。

### 3.3 导出

- **单份记录**：成绩页点「下载这份记录（CSV）」，逐题明细 + 合计。
- **全部记录**：汇总页点「导出全部记录（宽表 CSV）」，一行一个学生，
  列是 时间 / 卷别 / 正确数 / 总题数 / 正确率 / 用时 / 五个知识点 / 十道题的 0-1。

宽表可以直接拖进 Excel 或 pandas 做进一步分析。

## 4. 数据怎么读

### 4.1 认准配对明细，不要认总分对比

汇总页同时给出两个数：

- **前测平均 vs 后测平均** —— 这是**独立样本**（如果做前测和后测的不是同一批人）。
  这两个数的差**不能**直接算作教学效果，因为它混进了「这批人本来就强」的干扰。
- **配对明细** —— 同一个代号的前测和后测配起来，算每人自己的变化，再取平均。
  这是**配对样本**，消掉了个体差异。

界面上专门写了一段警告说明这件事。**要看效果，只看配对明细。**

### 4.2 五块知识点的变化

按知识点那张表能回答「哪一块提升了、哪一块没动」。这比一个总分有用得多 ——
如果总分涨了 20 个百分点但全部来自「示波器操作」，而「采样定理」纹丝不动，
那说明实验台对抽象概念的帮助有限，这是需要诚实报告的发现。

### 4.3 这份协议证明不了什么

必须说清楚，否则就是在过度承诺：

1. **样本小，不能做统计推断。** 5 个人的配对均值差，置信区间宽到没有意义。
   可以报告，但必须同时报告 n。
2. **不是随机对照试验。** 没有对照组，没有盲法。学生知道自己在做前测后测。
   练习效应（做第二遍本来就会好一点）无法排除 —— 锚题能部分缓解，不能消除。
3. **测的是选择题，不是动手能力。** 会算折叠频率 ≠ 会在真示波器上调出稳定波形。
   这份卷子测的是**概念理解**，不是操作熟练度。
4. **没有延迟后测。** 只有即时后测，说明不了长期保持。

这些局限应该写在 BP 里，而不是藏起来。**一个知道自己测不出什么的作者，
比一个声称什么都测出来的作者可信。**

## 5. 对照竞赛要求

自由命题要求原文：「方案（如何解决，并验证效果？）」，
效果验证的三种形式是「运行演示 · 试点验证 · 用户反馈」。

| 要求 | 本作品的对应物 |
| --- | --- |
| 运行演示 | 3 分钟 demo 视频 + 可直接双击打开的网页 |
| **试点验证** | **本协议**：5–10 人前测 / 后测配对，附锚题等值设计 |
| 用户反馈 | 同学 + 实验课教师的访谈记录（待补） |

---

## 6. 复现验证

出题引擎的正确性由自动化测试保证：

```bash
node app/test/quiz_smoke.js
```

52 项断言，覆盖：

- 两套卷子都是 10 题、五块知识点各 2 题
- 平行题的题干/选项/答案在前后测之间确实不同
- 锚题在前后测之间**完全一致**（题干、选项、正确答案文本）
- 判分正确（全对 10/10、全错 0/10、全空 0/10 且标为未作答）
- 每道带图的题都能真的画出图，且图上不出现答案
- CSV 导出格式（单份 + 宽表）
- 无 localStorage 时不崩

题目本身的正确性也逐题核对过：每道题的 `explain` 字段都写出了完整的推导链，
并且带图题的标准答案和图上读出来的值一致。
