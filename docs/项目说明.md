## 一、场景

**问题发生在哪个任务或流程里。**

电子信息类本科生在大一到大三之间有一条**断裂带**，它具体发生在两个地方：

**① 实验课上（教与学同时发生的地方）。**
学生第一次面对示波器面板上几十个旋钮，不知道时基和垂直档位各管什么，波形永远在屏幕上跑；老师挨个桌去调，一堂课下来真正用于「理解现象」的时间不到三分之一。下课铃响，学生把旋钮的用法连同仪器一起还给了实验室。

**② 课后自学（真正拉开差距的地方）。**
学生晚上对着课本推傅里叶变换，推得出来，但**「时域和频域到底是什么关系」说不清**；学完《电磁场与波》，天线阵列的导向矢量推得动，但**「阵列到底解决了什么问题」答不上来**。他们手上没有仪器，也没有人能在他们看图的那一刻说一句「你看到的这个，就是课本第 118 页在讲的东西」。

**这就是我们要插进去的位置：把「第一次看见现象」和「课本上那句话」之间的那段空白填上。**

## 二、用户

**谁遇到问题，谁会使用。**

| 角色 | 具体是谁 | 什么时候打开它 |
| --- | --- | --- |
| **主用户** | 电子信息 / 通信工程 / 自动化 本科生（大一到研一） | 课前预习（想先看看混叠长什么样）、课后复习（这道题里那个方波为什么是圆的）、实验课前后、考研复习 |
| **第二用户** | 实验课主讲教师与助教 | 备课时造演示波形；课后把「全班都卡在哪」拿到手；出一套分层练习题 |
| **第三用户** | 自学与转专业人群 | 没有实验室准入，也没有人答疑；需要「有反馈的练习」 |

**一个典型使用场景**：学生上完《信号与系统》的采样定理，回宿舍打开实验台，挑「混叠」预设，看到屏幕上一条 1 kHz 的正弦被显示成 500 Hz —— 他可以自己把采样率一格格拧下去，看假频率怎么随采样率变，再让 AI 助教解释为什么恰好是 500。**全程不需要服务器，不需要账号，不需要装任何东西。**

## 三、痛点

**现有做法哪里耗时、哪里不足。**

| # | 痛点 | 现有做法的具体不足 |
| --- | --- | --- |
| 1 | **仪器是黑箱** | 真实示波器有几十个旋钮，实验课时间有限，学生还没搞明白就该下课了；课后没有仪器可练。看教学视频是「别人拧」，自己没拧过。 |
| 2 | **知识是孤岛** | 傅里叶在高数里是个积分，在《信号与系统》里是个变换，在《通信原理》里是频谱，在《天线原理》里是方向图 —— **学生从没在同一件真实事物上看见过它们是同一个东西**。 |
| 3 | **反馈是延迟的、昂贵的** | 作业要等一周才批；问老师要排队；B 站视频不能回答「我刚才把带宽限制调到 4 会怎样」。**学习者得不到即时、针对眼前这一刻画面的反馈。** |
| 4 | **教师看不到班级的错法分布** | 批改只统计对错，不告诉你「这道题 60% 的人选了同一个错项」；想分层布置练习只能手编，编一套要一下午。 |
| 5 | **「学完不知道有啥用」** | 尤其是天线阵列：公式推得动，但不知道它解决什么问题。真实阵列实验要几万块的设备和一间暗室。 |

**现有替代品的不足**：MATLAB / Python 需要会写代码，且不解释现象；PhET / Falstad 类模拟器做得不错，但**是被动看**，学生不用自己判；MOOC 视频没法交互。**核心缺口是「先让学生自己判断，再给反馈」这一步。**

## 四、方案

**如何解决，并验证效果。**

### 4.1 做成了什么

一个网页实验台，左边一排旋钮，中间六台可交互仪器，右边一块「知识面板」实时解释你眼前的画面，再旁边一位 AI 助教。

| 仪器 | 学生能看到什么 | 对应课程 |
| --- | --- | --- |
| **信号发生器 + 示波器** | 波形、触发、时基与垂直档位；**混叠、超量程、触发丢失会自己冒出来** | 信号与系统、电路实验 |
| **频谱仪** | 谐波结构与扫宽的关系；方波少了高次谐波就变圆角 | 信号与系统、DSP |
| **时频图** | 非平稳信号才有的看；Δf 与 Δt 此消彼长，**乘积恒为 1** | DSP、通信原理 |
| **星座图** | 一个符号能塞几个比特，以及**抗噪能力就是「点距 vs 噪声圆圈」** | 通信原理 |
| **阵列测向** | Bartlett / MVDR / MUSIC 三条谱；波束宽度与瑞利限；MUSIC 的超分辨 | 天线原理、阵列信号处理 |
| **多径沙盒** | **只有一台发射机，阵列却报出好几个方向**（可自己拖楼和发射机） | 电磁场与波、无线信道 |

### 4.2 最关键的一个设计

**知识面板上的每一句话，都必须能从屏幕上当场量出来。**

比如方波在「带宽限制 = 4」时变圆角，面板不会只写「带宽受限导致波形失真」，而是给出：被保留的是第 1、3 次谐波，第 5 次开始被砍掉，这就解释了圆角。**没有一句是「课本说」—— 全部是「你屏幕上现在是」。**

### 4.3 效果验证怎么做

赛事要求「可验证」。我们准备了**三条证据路径**，按可信度从高到低：

**（1）与教科书公式对账 —— 已完成，657 项断言。**
每台仪器都不是「看起来像」，而是和闭式解逐档对账：

- 星座图的误符号率**现场对** M-PSK 与方阵 M-QAM 的教科书解析式，要求每一档信噪比下实测错误数都落在理论期望值的 4σ 内；
- 多径沙盒的四项几何自检（**入射角恒等于反射角**、起点—反射点—终点共线、路径长度等于各段之和）、法向入射 Γ = −0.402、掠入射 → −1、自由空间路损 1/L；
- 阵列的三条谱在单信源情形下峰值位置与真值一致，在相干多径情形下**复现出 MUSIC 报出虚假方向**这一现象（117 次运行每次都出现，而 Bartlett 一次都没有）。

**（2）工具链路端到端跑通 —— 已完成，88 份成绩单。**
出题 → 落盘 → 收卷 → 配对统计 → 错因分布 → 导出 CSV / 诊断文字，整条链路走通，44 项断言在验。**教师端会自己认出合成数据标记，并在报告顶上弹出橙色告示。**

**（3）真人前测 / 后测 —— 协议已就绪，待执行。**
带 4 道锚题的前测、后测各 10 题，五块知识点各 2 题；按 [`效果验证协议.md`](效果验证协议.md) 拉 5–10 位同学跑一次，并访谈 1–2 位实验课教师。

### 4.4 数据口径（重要，请连同这段一起使用）

> 效果验证目前提供的是**可复现的仿真试点队列** —— 88 份成绩单，种子固定、可重跑、可核查，用来验证「出题 → 收卷 → 配对统计 → 错因分布 → 导出」这条链路。它**不构成教学效果的证据**。真人前测 / 后测按本仓库 `docs/效果验证协议.md` 进行，完成后会如实替换。

**这一点我们在项目说明、报告首行、每一份 JSON 里都主动写明，不等对方问。** 理由很简单：本作品的技术主张是「每条结论都带证据、带不确定性」—— 数据来源上含糊一句，主张就自相矛盾了。

配套的诚实细节：仿真队列**刻意编出了真实课堂里一定会有的三类人**（6 人只交了前测就再没出现、6 份匿名卷配不上对、2 人没有前测），于是「前后测平均分直接相减」得到 +14 个百分点，而只算能配对的 38 个人是 +11.3 个百分点。**教师端会把这个坑直接点出来**，而不是给你一个好看的数字。

## 五、技术实现要点

1. **波形用截断傅里叶级数算，不是画出来的。** 方波 = 奇次谐波叠加，把「带宽限制」调低，高次谐波被真的砍掉。时域和频域在代码里就是同一个 `kMax`。
2. **采样是真的。** 示波器以 fs 对 s(t) 采样，fs < 2f 时屏幕上出现的波形是**算出来的**，不是动画。
3. **频谱用整周期同步 DFT。** 第 k 根谱线正好是第 k 次谐波，是精确的傅里叶系数。所以方波的基波幅度能和理论值 4/π 对上。
4. **多径沙盒不引第三方射线追踪。** 自己写二维镜像法 + 菲涅尔系数 + 矩形遮挡：物理是真的，代价是只做二维、只到 2 阶反射 —— 对「多径为什么让测向失效」这一个教学点够了，换来的是「双击即用」。
5. **离线优先。** 实时信号合成与频谱都是纯 JavaScript，断网、无服务器也能跑完整演示。
6. **AI 助教拿得到全部仪器状态。** 它不是通用聊天框：学生一问，它收到的是一份结构化的现场描述（当前波形参数、采样率、触发电平、谱线、阵列谱、时频窗长、星座噪声、沙盒路径表），所以它能回答「我刚才把窗长调到 512 会怎样」这种问题。
