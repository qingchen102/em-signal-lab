# 演示脚本

面向两个场合：现场走一遍（8 分钟），以及交上去的 3 分钟视频（`demoFileId`）。

稿子是给人念的，里面的数字都是真的，每个能说出口的数都在测试或报告里验过。

---

## 〇、开场前 3 分钟自检

| 检查 | 命令或动作 | 不对会怎样 |
| --- | --- | --- |
| 页面能开 | 双击 `app/index.html` | 整场没得演 |
| AI 助教能用 | `python app/server.py`（另开一个窗口，会自己开浏览器） | 讲到 AI 那一段只能尴尬地说这个要联网 |
| 预设条能滚 | 鼠标在预设条上横向滚一下 | 多径沙盒那 4 个预设点不到 |
| 教师端有数据 | 教师端 → 看全班 → 拖 `pilot/cohort-all.json` | 教师端是空的 |
| 音量与字号 | 浏览器 Ctrl+= 放大到 125% | 后排看不见右栏的读数 |

六台仪器、沙盒、题库、教师端全部离线。只有 AI 助教需要本机那个 `server.py`。

## 一、30 秒电梯稿（评委打断你时用这段）

> 电子信息的学生学《信号与系统》《通信原理》，课本上是公式，实验室里是黑箱。示波器不会调，时域频域分不清，学完天线阵列不知道它有什么用。三个卡点，全在看不见上。
>
> 信号实验室把六台仪器搬进浏览器。造一个信号，拧几个旋钮，屏幕上出现的就是真的采样、真的 DFT、真的 MUSIC 谱。旁边坐一位 AI 助教，它拿得到你所有旋钮的位置，先讲现象再讲原理。
>
> 它不是演示动画。每台仪器都跟教科书公式对过账，657 项断言加 44 项试点校验，全过。双击一个 HTML 文件就能跑，零依赖、不联网。

## 二、现场演示 · 8 分钟逐屏

每一屏都按同一个句式：做什么、说什么、为什么这屏排在这儿。

### 0:00 到 0:40 ｜第一屏：那台不会调的示波器

| | |
| --- | --- |
| 打开 | `app/index.html?preset=时基太快` |
| 说 | 这是大一那个下午，屏幕上只有一个点。不是仪器坏了，是时基太快，一屏只采到一个周期。往慢拧两格，波形自己就出来了。 |
| 为什么 | 一上来不讲产品，讲所有人经历过的那个下午。这一屏的作用是让人觉得这说的是我。 |

顺手再点一下 `?preset=触发丢失`（波形在屏幕上乱跑），说一句触发就是这么回事。

### 0:40 到 1:20 ｜第二屏：采样定理，屏幕上看得见

| | |
| --- | --- |
| 打开 | `?preset=混叠` |
| 说 | 1 kHz 的正弦，采样率拧到 1.5 kSa/s。屏幕上这条 500 Hz 的波是真的算出来的，不是画上去的，它就是把采样点连起来的结果。红线是 fs/2，它右边那根本来该在 1 kHz 的谱线，折到了 500 Hz。 |
| 为什么 | 采样定理是所有后续内容的门槛。学生背过公式，但从没见过它在屏幕上骗人。 |
| 别踩 | 不要说混叠会失真这种课本话。说屏幕上显示的是假的，这个说法学生一次就记住。 |

### 1:20 到 2:00 ｜第三屏：时域和频域是同一个东西

| | |
| --- | --- |
| 打开 | `?preset=方波与谐波`，再点 `?preset=带宽限制` |
| 说 | 方波是无数个奇次谐波叠出来的。把带宽限制拉到 4 次，示波器上它自己就变圆了。注意，我没画圆它，我是真的把高次谐波砍掉了。 |
| 为什么 | 这是整个项目最硬的技术主张：波形是算出来的，不是画的。同一屏上时域加频谱，谁看谁明白。 |

### 2:00 到 3:00 ｜第四屏：天线阵列到底有啥用

| | |
| --- | --- |
| 打开 | `?preset=阵列测向`，再切 `?preset=分不开的两个方向` |
| 说 | 下面这是 8 个阵元排成一行。上面三条线是三种测向算法：Bartlett、MVDR、MUSIC。两个信号只差 12 度，Bartlett 只有一个鼓包，MUSIC 长出了两个峰。这就是你多花的那几个小时算力买到的东西。 |
| 为什么 | 这是用户最初点名的第三个痛点，也是最抽象的一个。用同一张图上的一个峰对两个峰来回答它，不需要讲子空间。 |
| 加一句 | MUSIC 为什么行得通、什么时候会翻车，后面第五屏会打它自己的脸。（埋伏笔） |

### 3:00 到 3:50 ｜第五屏：星座图，一个符号能塞几个比特

| | |
| --- | --- |
| 打开 | `?preset=QPSK 星座图`，再 `?preset=升到 64QAM`，再 `?preset=给 64QAM 补 9 dB` |
| 说 | QPSK 一个符号塞 2 bit，64QAM 塞 6 bit，但点距从 1.41 掉到 0.31。红圈是判错的符号：同一档信噪比下 QPSK 一个都不错，64QAM 错了四分之一。补 9 dB，它又干净了。频谱效率是用抗噪能力换的，没有免费午餐。 |
| 为什么 | 这是通信原理里效率与可靠性的那个权衡，学生考完就忘。这里是拖一条信噪比滑条就能看见的。 |
| 硬货 | 右下角两行 SER：仿真值和理论闭式解，每档信噪比都落在理论 4σ 内。有人问这数是你编的吗，指这里。 |

### 3:50 到 5:00 ｜第六屏：多径沙盒

| | |
| --- | --- |
| 打开 | `?preset=一台发射机，三个方向` |
| 说 | 现在只有一台发射机。楼是自己摆的，可以拖着玩。到达阵列表面的路径有五条：一条直达，两条从两面墙上各弹一次，两条弹两次。上面那条蓝色的谱，阵列报出了三个方向。 |
| 停一拍再说 | 阵列没坏。它看到好几个方向，是因为这几个方向上真的有能量进来。这就是城市里做测向最难的地方。 |
| 再切 | `?preset=楼把直达挡死了`。楼把直线挡死了，实测报出 43°，发射机的真实方位是 0°，差了 43 度。 |
| 为什么 | 这是沙盒存在的唯一理由：把多径让测向失效从一个名词变成一张能拖着玩的图。 |
| 硬货 | 引擎是自己写的二维镜像法：菲涅尔反射系数 εr=5.5、法向入射 Γ=−0.402、掠入射趋近 −1。测试里逐项对账，入射角恒等于反射角。 |

### 5:00 到 6:20 ｜第七屏：效果验证，凭什么说学生学会了

| | |
| --- | --- |
| 打开 | 顶栏「效果验证」→ 前测 → 随便答两题 → 退出 → 点「看汇总」 |
| 说 | 教学类作品最容易滑向的失败模式是演示很好看，但没有任何证据说明学生学会了。所以内置了前测与后测：10 道题覆盖五块知识点，6 道平行题换数字，4 道锚题一字不差。锚题是关键，没有它，你分不清是学生变强了还是后测那套更简单。 |
| 别踩 | 不要在答案里选太多次。这是演示流程，不是产品在判断你。 |
| 诚实 | 目前还没有一个班的真实数据，协议已经写好，见 `docs/效果验证协议.md`。我们已经用一份可复现的仿真队列把工具链路跑通了。 |

### 6:20 到 8:00 ｜第八屏：教师端，收口

| | |
| --- | --- |
| 打开 | 顶栏「教师端」→「看全班」→ 拖入 `pilot/cohort-all.json` |
| 说 | 这是 88 份成绩单。先说清楚，这批是合成数据，不是真学生，你看它自己就弹了这条橙色告示。（指那条 banner） |
| 指着念 | 前测 45%、后测 59%。但这两个数不能直接减，做题的人不是同一批：有 6 个人只交了前测就再没出现，他们前测只有 33.3%。只算前后测都交、能配对的 38 个人，是 +11.3 个百分点。相减法会给你 +14，那是把掉队的人算进分母吹出来的。 |
| 再指 | 最有用的不是平均分，是这三条卡点：采样定理只有 38% 对，26 个人选了同一个错项。老师拿到的是哪个知识点错了、错在哪个思路上，不是第 3 题错的人多。 |
| 收尾 | 「出练习」页签，按这三个卡点生成一份分层练习，点「打印 / 存 PDF」。从发现卡点到明天上课用的卷子，中间是零次手动出题。 |
| 为什么 | 这一屏回答评委心里那个问题：这东西谁付钱。老师愿意为省掉出卷子和改卷子付钱。 |

### 收尾 20 秒

> 整套东西是一个 HTML 文件。双击就开，不装环境、不联网、不注册。657 项断言是它敢这么做的底气。

## 三、录屏版（交上去的 `demoFileId`）

成片是 `submission/信号实验室-demo.mp4`，1 分 34 秒，1440×900，中文旁白、逐句中文字幕、轻微的转场声，十章。每章开头压黑 0.34 秒切过去，随即在画面上方浮出一块标题卡：章号、章名，和一句话说明这一章要演示什么。

| 时间 | 章 | 画面里在做什么 |
| --- | --- | --- |
| 0:00 | 信号实验室 | 打开就是一个网页，没有登录框 |
| 0:07 | 混叠 | 1.5 kSa/s 采 1 kHz，屏幕上是一条 500 Hz 的波；把采样率拖上去，它变回 1 kHz |
| 0:21 | 方波与谐波 | 谐波落在基波整数倍上，拖动频率，整排谱线跟着走 |
| 0:32 | 带宽限制 | 带宽拖到最窄，方波自己变圆 |
| 0:38 | 多径沙盒 | 一台发射机五条来波，拖动一栋楼，路径和测向结果实时重算 |
| 0:48 | 直达被挡 | 街角，只剩一条反射，测出来的方向偏了 43 度 |
| 0:55 | 教师端 | 88 份成绩单拖进弹层，一眼看到卡点 |
| 1:03 | 出练习 | 选知识点和难度，生成练习卷 |
| 1:11 | AI 助教 | 问它为什么测不准，它照着路径表一步一步讲 |
| 1:28 | 收尾 | 回到示波器，纯前端零依赖 |

录屏是脚本驱动真浏览器录的，不是幻灯片：`demo/record.js` 通过 CDP 往页面里派发真实的鼠标按下、移动、抬起事件，滑条是被按住拖的，楼是被按住拖的。画面里那个白点是注入的可见光标，方便看清操作位置。配音是 `edge-tts` 合成的旁白，逐章按章节时长对齐；字幕用的就是合成时返回的逐句时间戳，不是事后猜的。标题卡与转场都是同一份 ASS 里画的，没有另做剪辑。重跑流程见 `demo/README.md`。

要点：

- AI 那一段要先确认 `server.py` 在跑，否则录出来是报错；
- 每一章停留不少于六秒，让画面里的数字有机会被看清；
- 旁白里不要念参数名，念现象。

## 四、三个高频追问

问：这不就是 MATLAB 或者罗德频谱仪的图吗？

> 图长得像，位置不一样。MATLAB 是给会写代码的人用的，这台仪器是给还没学会的人用的，他不需要写一行代码，拧旋钮就行。而且我们不做给出结论这件事，我们让他先自己判，再对答案。这是教学工具和测量工具的分界。

问：AI 在哪儿，不就是个套壳聊天框？

> 把 `brief()` 拼的东西打开给评委看：仪器状态、真实采样结果、折叠公式的数值、学生最近三次动的旋钮，全都进了 system prompt。它回答你这个峰是不是真的，靠的是我们喂进去的实测 Bartlett 谱，不是语言模型的常识。另外 AI 的位置是助教不是判官，每道题的正确答案是 `quiz.js` 的答案键算的，不是模型生成的。

问：合成数据，那不就是假的吗？

> 分两层。软件链路是真的，这 88 份走的是 `packRecords` 到落盘、`readRecords`、`aggregate` 的真实代码路径，没有任何为演示特供的分支，`verify_cohort.js` 的 44 项断言就在验这条路。教学效果是未知的，那需要真学生，协议已经写好了。素材里每一处引用这三个数字的地方，都带着合成数据字样。
>
> 口径已经拍板：主动写明，不等别人问。项目说明、演示视频、答辩 PPT 里只要出现这三个数字，就配一句：
>
> > 效果验证目前提供的是可复现的仿真试点队列：88 份成绩单，种子固定、可重跑、可核查，用来验证「出题、收卷、配对统计、错因分布、导出」这条链路。它不构成教学效果的证据。真人前测与后测按本仓库 `docs/效果验证协议.md` 进行，完成后会如实替换。
>
> 主动写明比被动承认强得多。对方问出这个问题时，你答我们自己在报告首行就标了，这一段就成了加分项。

## 五、千万别做的五件事

1. 别说「我们的试点证明提升了 11.3%」。那份数据是合成的。说「我们用仿真队列跑通了工具链路，真试点协议已就绪」。
2. 别在没开 `server.py` 的情况下点 AI 助教。报错画面比不讲 AI 更伤。
3. 别在 64QAM 那一屏把信噪比拉满。干净得看不出问题，就讲不了那个权衡。
4. 别从「我们用了什么算法」开始讲。从那个只显示一个点的示波器开始。
5. 别把「25 个预设」当卖点念。那是给演示省事用的，不是产品价值。

## 六、一句话记住这场演示的主线

> 看不见，看得见，自己判，有证据。

示波器是看不见，六台仪器加沙盒是看得见，前测后测加教师端是自己判和有证据。每一步都配一个凭什么信：657 项断言、44 项试点校验、理论闭式解、教科书公式。
