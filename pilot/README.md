# 仿真试点队列

> ## ⚠️ 这个目录里的一切都是**合成数据，非真实学生**
> `cohort/` 下每一份成绩单、`cohort-all.json`、`报告样例.md`，全部由
> [`make_cohort.js`](make_cohort.js) 用种子 `20261016` 生成。题目是真的（取自
> `app/js/quiz.js` 的真题面），**答题的人是假的**。
>
> 它不能当试点结果用。把它拿到任何评审面前时，必须带上这句话。

---

## 一、为什么要有这个目录

赛事对效果验证的要求是「运行演示 · 试点验证 · 用户反馈」三选一。真实试点要拉一个班、
做前测、做完教学、做后测，周期以周计 —— 在本项目的时间窗口里做不到。

于是分成两件事，而不是拿假数据冒充真试点：

| | 是什么 | 现在能不能用 |
| --- | --- | --- |
| **本目录** | 一份**可复现的仿真队列**，用来证明「教师端拿到 88 份卷子真的能跑出结论」，也就是**运行演示** | ✅ 现在就能演 |
| **[`../docs/效果验证协议.md`](../docs/效果验证协议.md)** | 真试点的操作规程：找谁、怎么配对、怎么算、怎么报告 | 协议已就绪，人还没拉 |

这条分界是刻意的。合成数据能证明**软件是对的**，证明不了**教学是有效的** —— 后者只有真学生能证明。

## 二、目录清单

| 路径 | 是什么 |
| --- | --- |
| `make_cohort.js` | 生成器。跑一次就把整个队列重新算出来（确定性，同种子同结果） |
| `verify_cohort.js` | 校验器。44 项断言，检查队列与报告是否符合设计意图；顺便写出 `报告样例.md` |
| `cohort/` | 88 份单人成绩单，每份一个 JSON。文件名形如 `合成-S01-pre.json` |
| `cohort-all.json` | 88 份合并成的一份（教师端「看全班」可以直接吃这个文件） |
| `报告样例.md` | 校验器输出的报告快照，给路演和文档引用 |

每份 JSON 的内部长这样（顶层多出来的两个字段是给肉眼看的，教师端读入时只取 `records`）：

```json
{
  "app": "signallab",
  "kind": "quiz-records",
  "version": 1,
  "synthetic": true,
  "note": "合成数据，非真实学生（pilot/make_cohort.js 生成）",
  "who": "S01",
  "records": [ { "form": "pre", "who": "S01", "ms": 412000, "finishedAt": "...", "score": { ... } } ]
}
```

## 三、队列是怎么编的

刻意编出了真实课堂里一定会出现、而"理想数据"里一定没有的三种人：

| 人群 | 人数 | 编出来的特征 | 存在意义 |
| --- | --- | --- | --- |
| 两卷都交 | 38 | 后测比前测好 | 用来算配对提升，这是**唯一**说得清"学会了没有"的数 |
| 只交了前测 | 6 | 前测平均只有 33.3%，明显低于能配对的那批（48.4%） | 制造"掉队的人本来就差"这个偏差 |
| 匿名卷 | 6 份 | 没填代号，无法配对 | 制造"不是所有卷子都能进配对"这个现实 |
| 只交了后测 | 2 | 中途转进来的 | 制造"有人没有前测基线" |

总分：**88 份卷子 / 44 个有代号的人 / 6 份匿名**。

这四种人凑在一起，就出现了那个关键对照：

- 「前后测所有人的平均分直接相减」→ **+14 个百分点**
- 「只算配对的 38 个人」→ **+11.3 个百分点**（48.4% → 59.7%）

差的这 2.7 个点不是舍入误差，是那 6 个掉队的人被算进了前测分母。**教师端会在报告里
把这个坑直接点出来**，而不是默默用错的算法给你一个更好看的数字。

## 四、怎么跑

```bash
cd em-signal-lab
node pilot/make_cohort.js      # 生成 88 份成绩单到 pilot/cohort/
node pilot/verify_cohort.js    # 44 项断言 + 输出 pilot/报告样例.md
```

两个脚本都是纯 Node、零依赖，只用 `app/js/` 里的项目自己的代码
（`quiz.js` 的真题面 + `teacher.js` 的统计引擎），所以**它们同时也是集成测试**：
`make_cohort.js` 走的是真实的 `packRecords → 落盘 → readRecords → aggregate` 这条路，
没有一点为演示特供的分支。

`verify_cohort.js` 的 44 项断言覆盖三块：队列本身是否符合设计（人数、缺考、匿名）、
统计引擎是否算对（配对提升、知识点分档、卡点挑选）、导出的 CSV 与诊断文字是否可以
直接给人看（没有 `NaN`/`undefined`、段落数、三个卡点都不高于 70%）。

## 五、怎么在教师端上用它（运行演示的脚本）

1. 打开 `app/index.html`，点右上角 **教师端**；
2. 切到 **看全班** 页签；
3. 把 `pilot/cohort-all.json` 拖进虚线框（或者点「选择文件」多选 `cohort/` 里的几十份）；
4. 报告立刻出来 —— 概览卡、配对说明、知识点表、三个卡点、逐题表；
5. 点 **导出 CSV** 给教研组，点 **导出诊断** 给老师；
6. 切回 **出练习** 页签，按卡点选「采样定理 + 时域基本量」，层次选「基础」，
   生成一份分层练习，点 **打印 / 存 PDF**。

整条链路不需要联网、不需要后端、不需要账号。

## 六、真试点怎么做

合成数据止步于此。要拿到能写进 BP 的真实数字，按
[`../docs/效果验证协议.md`](../docs/效果验证协议.md) 走：

1. 找一个班（本科 2～3 年级、正在上或刚上完《信号与系统》/《通信原理》）；
2. 课前做前测（10 题，约 8 分钟，扫个二维码）；
3. 正常上课，学生课后用实验台自己玩，老师用教师端出分层练习；
4. 课后做后测（同结构、锚题一字不差）；
5. 用教师端的 **看全班** 出报告，**只报配对提升**，并且在报告里写明掉队人数。

真实数据进来时，`cohort/` 里这些合成文件应当被清掉或挪走 —— 别让它们和真数据混在一个目录里。

## 七、边界（写在最后，免得被忘掉）

- ❌ 不能引用本目录的任何数字作为「教学效果」的证据；
- ❌ 不能把 `报告样例.md` 的截图当试点结果展示（除非画面上带着"合成数据"字样）；
- ✅ 可以引用它证明**软件功能完整**（教师端能读 88 份、能配对、能挑卡点、能导出）；
- ✅ 可以用它做路演和答辩的现场演示，**前提是当场说明这是仿真队列**。

一句话：**这份数据证明的是「工具跑得通」，不是「学生学得好」。**
