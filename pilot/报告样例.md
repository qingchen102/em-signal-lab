# 全班报告样例 —— **合成数据，非真实学生**

> 这份报告由 `pilot/cohort/` 下的**仿真队列**跑出来，**不是任何一次真实的前测 / 后测**。
> 队列由 `pilot/make_cohort.js` 生成（种子 20261016），题目取自 `app/js/quiz.js` 的真题面。
> 真试点请按 [`../docs/效果验证协议.md`](../docs/效果验证协议.md) 去拉人。

生成命令：`node pilot/make_cohort.js && node pilot/verify_cohort.js`

## 一、教师端看到的诊断

```
收到 88 份成绩单，涉及 44 个代号（其中 6 份没填代号）。
前测 48 份，平均正确率 45%；后测 40 份，平均正确率 59%。这两个数不能直接减 —— 做题的人不一样。
前后测都做了、能配对的 38 个人：平均从 48.4% 到 59.7%，提高 11.3 个百分点。这个数才说得清「学会了没有」。

全班最集中的三个卡点：
1. 时域基本量（前测的 t1 类题型）正确率 25%（12/48）；最常见的错法是选「4.0 kHz」，32 个人这么选
2. 采样定理（前测的 s1 类题型）正确率 38%（18/48）；最常见的错法是选「5.0 kHz」，26 个人这么选
3. 频谱与谐波（前测的 p1 类题型）正确率 40%（19/48）；最常见的错法是选「500 Hz」，20 个人这么选
```

## 二、概览

| 项 | 值 |
| --- | --- |
| 收上来的卷子 | 88 份 |
| 有代号的学生 | 44 人 |
| 匿名卷 | 6 份 |
| 前测 | 48 份，平均 45% |
| 后测 | 40 份，平均 59% |
| **配对**（同名同卷别都交了） | 38 人 |
| **配对的平均提升** | **+11.3 个百分点**（48.4% → 59.7%） |
| 前后测所有人的平均分相减 | 14 个百分点 ← 这个数是**错**的 |

最后两行是同一批数据、两种算法。差别不是舍入误差，是**掉队的人本来就差**：

| 人群 | 前测平均 | 人数 |
| --- | --- | --- |
| 两卷都交了的（能配对的） | 48.4% | 38 |
| **只交了前测、再没出现的** | **33.3%** | 6 |
| 匿名卷（前测） | 35% | 4 份 |

「前后测所有人平均分相减」把前两行混在一起算，等于假设那 6 个人如果交了后测会考得跟别人一样 —— 可他们本来只有 33.3%。
他们被算进分母，前测平均被拉低，于是提升被吹大：相减法给出 +14，配对法给出 +11.3。

这不是这份合成数据编出来的毛病。真实课堂里，半途掉队的、翘考的、不愿填代号的，
往往就是学得吃力的人。**只算配对的那批人**，才是能说清「学会了没有」的算法。
